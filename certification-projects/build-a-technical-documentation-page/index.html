HTML and CSS

HTML provides the structure of a web page, while CSS controls its visual presentation and layout.

A basic document uses semantic HTML elements and can be styled with an external stylesheet such as <link rel="stylesheet" href="styles.css">.

  1. HTML defines the structure and content.
  2. CSS controls layout, colors, spacing, and typography.
JavaScript

JavaScript adds behavior and interactivity to web pages. It can respond to user actions and manipulate the document.

Developers can use the browser console to test JavaScript expressions and inspect application behavior.

  1. Variables store application data.
  2. Functions organize reusable logic.
  3. Events allow applications to respond to user interaction.

A simple message can be displayed with console.log("Hello World");.

Python and Django

Python is a general-purpose programming language commonly used for backend development, automation, and data-related tasks.

Django is a Python web framework that provides tools for building structured and maintainable web applications.

  1. Python provides the programming language.
  2. Django provides the web application framework.
  3. Applications can be organized into reusable components.

A Django development server can be started with python manage.py runserver.

APIs

An API allows different software systems to communicate with each other through defined requests and responses.

Web APIs commonly use HTTP methods to work with resources. Common methods include GET, POST, PUT, PATCH, and DELETE.

  1. GET retrieves data from a resource.
  2. POST sends data to create a resource.
  3. PUT or PATCH updates an existing resource.
  4. DELETE removes a resource.

A client can request data from an endpoint such as /api/products/.

Development Workflow

A consistent development workflow makes projects easier to maintain, test, and collaborate on.

Version control systems such as Git allow developers to track changes and work safely with branches.

  1. Plan the feature or problem to be solved.
  2. Implement the required changes.
  3. Test the application.
  4. Commit the completed work with a clear message.
  5. Review and deploy the project when appropriate.

A common Git workflow starts with git status to inspect the current repository state.
